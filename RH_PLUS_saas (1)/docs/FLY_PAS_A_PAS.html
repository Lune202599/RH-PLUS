Chaque étape indique la commande exacte à copier, ce que vous devez voir apparaître, et le piège à éviter. Les commandes ont été exécutées et vérifiées sur une machine de test avant d’être écrites ici.

0

Avant de commencer

durée estimée : 5 min

Tout est déjà préparé dans le ZIP : fly.toml, deploy/Dockerfile.fly, deploy/fly-entrypoint.sh. Vous n'avez qu'à suivre les étapes.

Ce qu'il vous faut

  • un compte Fly.io (création gratuite, carte bancaire demandée pour la vérification — non débitée à l'inscription) ;
  • un terminal (Linux, macOS, ou PowerShell sous Windows) ;
  • le ZIP RH_PLUS_saas.zip décompressé sur votre poste ;
  • votre boîte email professionnelle (pour l'envoi des codes de connexion).

Ce que ça coûte

Machine shared-cpu-1x 512 Mo, allumée≈ 3,30 $
Volume 1 Go (base, clé, coffre-fort)≈ 0,15 $
Trafic sortant (premiers Go)inclus
Total mensuel≈ 3,5 $ ≈ 2 000 FCFA

Fly.io n'a plus d'offre gratuite pour les nouveaux comptes. Si vous voulez du gratuit, voir docs/DEPLOIEMENT_GRATUIT.md (Oracle Cloud Always Free).

Piège à éviter : Deux règles qui, si elles sont violées, font perdre vos données : une seule machine (jamais fly scale count 2) et un volume obligatoire.
1

Installer l’outil Fly et se connecter

durée estimée : 3 min

L'outil en ligne de commande s'appelle flyctl. Il fait tout : création de l'application, du volume, des secrets, déploiement.

bash
# Linux et macOS
curl -L https://fly.io/install.sh | sh

# Windows (PowerShell)
iwr https://fly.io/install.ps1 -useb | iex

# puis, dans un nouveau terminal :
fly version
fly auth signup        # création de compte (ou « fly auth login » si vous en avez déjà un)
Si le message « fly: command not found » apparaît, fermez puis rouvrez le terminal : le chemin est ajouté à l’ouverture d’une nouvelle session.
Ce que vous devez voir : une version affichée (par exemple flyctl v0.3.x) et, après fly auth signup, un message de confirmation de connexion à votre compte.

Ce qui se passe à l'inscription

Fly demande un moyen de paiement (carte bancaire) pour vérifier votre identité. Rien n'est prélevé à l'inscription : la facturation commence quand votre machine tourne. Vous pouvez fixer une alerte de budget dans Dashboard → Billing → Spend limits.

2

Se placer dans le dossier du projet

durée estimée : 1 min

Toutes les commandes suivantes se lancent depuis le dossier qui contient fly.toml et package.json.

bash
unzip RH_PLUS_saas.zip -d rhplus-saas
cd rhplus-saas

# vérification : ces deux fichiers doivent exister
ls fly.toml package.json deploy/Dockerfile.fly
Les trois noms de fichiers doivent s’afficher. Si fly.toml est absent, vous n’êtes pas dans le bon dossier.
Ce que vous devez voir : fly.toml, package.json et deploy/Dockerfile.fly sur la même sortie de commande.
3

Créer l’application (sans déployer tout de suite)

durée estimée : 5 min

L'option --copy-config indique à Fly d'utiliser le fly.toml fourni (volume, HTTPS, machine unique, vérification de santé).

bash
fly launch --no-deploy --copy-config

Les questions posées, et la réponse à donner

Question de FlyVotre réponse
« An existing fly.toml file was found. Would you like to copy its configuration? »Yes
« Choose an app name » (le nom rhplus-saas est déjà pris)un nom unique, ex. rhplus-saas-votrenom
« Choose a region »cdg (Paris) ou jnb (Johannesburg, plus proche du Gabon)
« Would you like to set up a PostgreSQL database? »No
« … Redis / Upstash ? »No
« Would you like to deploy now? »No

Le logiciel utilise SQLite sur son volume : aucune base externe n'est nécessaire (et elle coûterait plus cher).

Ce que vous devez voir : un message du type Created app 'rhplus-saas-votrenom' in organization 'personal'.
4

Créer le volume de données (l’étape à ne pas sauter)

durée estimée : 2 min

Le volume est le disque qui garde la base, la clé de chiffrement et le coffre-fort entre deux déploiements. Sans lui, tout est effacé à chaque mise à jour.

bash
# la région doit être la même que celle de l'application
fly volumes create rhplus_data --size 1 --region cdg --yes
Ce que vous devez voir : une ligne du type Created a 1GB volume named 'rhplus_data' in region cdg.
Piège à éviter : si vous déployez à Johannesburg, remplacez cdg par jnb. Un volume dans une autre région que la machine ne peut pas être monté.

Pourquoi 1 Go suffit

La base, la clé, les documents du coffre-fort et 14 sauvegardes représentent quelques dizaines de Mo pour des milliers de bulletins. Vous pourrez agrandir le volume plus tard sans perdre les données.

5

Renseigner les secrets

durée estimée : 5 min

Les secrets sont des variables protégées : elles ne sont pas écrites dans le code et restent chiffrées chez Fly.

bash
# 1) la clé de chiffrement : elle protège les numéros CNSS et le coffre-fort
fly secrets set RHPLUS_MASTER_KEY=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")

# 2) premier essai : démarrer même sans passerelle SMS/email
fly secrets set RHPLUS_ALLOW_CONSOLE_MESSAGING=1
L’étape 1 génère une clé aléatoire de 32 octets et l’envoie à Fly. Conservez-la dans un gestionnaire de mots de passe : sans elle, les données chiffrées deviennent définitivement illisibles.
Ce que vous devez voir : après chaque commande : Secrets are staged for the next deployment!
Piège à éviter : ne mettez jamais RHPLUS_MASTER_KEY dans un fichier versionné ou dans un message. Si vous la perdez, repartez de zéro (aucune récupération n’est possible, c’est le principe même du chiffrement).

Et l'envoi réel des codes ? (étape 10)

Vous les ajouterez une fois le site en ligne et l'adresse email professionnelle prête : c'est l'étape 10. Elle est nécessaire avant toute utilisation avec de vrais salariés.

6

Déployer

durée estimée : 5 à 10 min

Cette commande construit l'image, l'envoie chez Fly, monte le volume et démarre la machine.

bash
fly deploy

Ce qui se passe, dans l'ordre

  1. construction de l'image (installation des dépendances incluses : comptez 2 à 4 minutes la première fois) ;
  2. envoi de l'image et création de la machine ;
  3. montage du volume sur /data — le point d'entrée fourni s'approprie le volume puis abandonne les privilèges (sans lui, l'application planterait avec EACCES) ;
  4. vérification de santé sur /api/health ;
  5. mise en ligne de l'adresse https://<votre-app>.fly.dev avec HTTPS automatique.
Ce que vous devez voir : à la fin : Visit your newly deployed app at https://rhplus-saas-votrenom.fly.dev/, et fly status qui affiche une machine en started.
Piège à éviter : si la machine redémarre en boucle avec le message « ARRÊT : envoi des notifications non configuré », c’est que le secret RHPLUS_ALLOW_CONSOLE_MESSAGING de l’étape 5 n’a pas été posé — c’est le garde-fou du logiciel, pas une panne.
7

Vérifier que ça tourne

durée estimée : 2 min

Deux vérifications : la santé du service, puis l'affichage réel de la console.

bash
# 1) la machine et ses ports
fly status
fly logs            # doit afficher : « Environnement : production », l'adresse, l'état des notifications

# 2) la santé du service depuis internet
curl https://rhplus-saas-votrenom.fly.dev/api/health
Ce que vous devez voir : {{"ok":true,"service":"RH PLUS API","version":"0.1.0","env":"production",…}}
8

Créer votre compte administrateur plateforme

durée estimée : 2 min

Le compte qui administre les entreprises clientes. Il se crée sur la machine, pas sur votre poste.

bash
fly ssh console -C "gosu node node scripts/create-platform-admin.js \
  --email=vous@rhplus.ga --name='Votre nom' --password='UnMotDePasse#2026'"
gosu node est indispensable : il fait exécuter la commande sous le compte sans privilèges. Sans lui, le fichier de base appartiendrait à root et l’application ne pourrait plus y écrire.
Ce que vous devez voir : encadré « Compte plateforme RH PLUS créé », avec l’email et le rôle platform_admin.

Ajouter des données de démonstration (facultatif)

Pour montrer le logiciel à un client avec un jeu d'essai complet (entreprise « Lune Digital », 6 salariés) :

fly ssh console -C "gosu node npm run seed"

À ne pas faire sur une base contenant déjà de vraies données : la commande remet la démonstration à zéro (elle conserve votre compte plateforme).

9

Votre première connexion

durée estimée : 2 min

Hors production, le code s'affiche à l'écran. En production, il est envoyé par SMS et email : à l'étape 5, ce n'est pas encore le cas, donc le code se lit dans les journaux.

bash
# après avoir saisi votre email et votre mot de passe, récupérez le code :
fly logs
Repérez la ligne « RH PLUS — votre code de connexion : 123456 », saisissez-le dans la fenêtre de vérification.
Piège à éviter : connexion impossible alors que le compte a bien été créé ? Vous l’avez probablement créé sur votre poste et non sur la machine : reprenez l’étape 8 avec fly ssh console.
10

Activer l’envoi réel des codes (obligatoire avant tout client)

durée estimée : 10 min

C'est le blocage principal du projet : sans envoi réel, personne d'autre ne peut se connecter. Le logiciel refuse de démarrer en production sans canal configuré — c'est voulu.

bash
fly secrets set \
  RHPLUS_MAIL=smtp \
  RHPLUS_MAIL_FROM="RH PLUS " \
  RHPLUS_SMTP_HOST=smtp.votre-fournisseur.ga \
  RHPLUS_SMTP_PORT=587 \
  RHPLUS_SMTP_SECURE=false \
  RHPLUS_SMTP_USER=notifications@rhplus.ga \
  RHPLUS_SMTP_PASS='votre-mot-de-passe-smtp' \
  RHPLUS_SMS=http \
  RHPLUS_SMS_SENDER=RHPLUS \
  RHPLUS_SMS_URL='https://passerelle.exemple.ga/send?to={to}&text={text}&sender={sender}&key={key}' \
  RHPLUS_SMS_KEY='votre-cle-sms'

# une fois l'essai terminé : retirer le mode démonstration, puis redéployer
fly secrets unset RHPLUS_ALLOW_CONSOLE_MESSAGING
fly deploy

Comment tester sans attendre

Connectez-vous avec le compte plateforme, onglet Plateforme → Envois de notifications : saisissez une adresse et un numéro, cliquez Tester. Le journal indique pour chaque canal s'il est configuré et si l'envoi a réussi. Détail des passerelles SMS acceptées : docs/NOTIFICATIONS.md (Airtel, Moov, Africa’s Talking, API HTTP générique).

Ce que vous devez voir : dans l’écran Plateforme : Email : smtp (prêt) · SMS : http (prêt) et un statut « envoyé » dans le journal des messages.
11

Brancher votre nom de domaine

durée estimée : 10 min + DNS

Pour que vos clients voient rhplus.ga plutôt qu’une adresse fly.dev.

bash
fly certs add rhplus.ga
fly certs show rhplus.ga      # affiche l'enregistrement DNS exact à créer

# chez votre registrar (OVH, Namecheap, .ga…) :
#   type A   , nom @   , valeur = l'adresse IP affichée par « fly ips list »
#   type AAAA, nom @   , valeur = l'adresse IPv6 affichée
#   type CNAME, nom www, valeur = rhplus-saas-votrenom.fly.dev

fly certs check rhplus.ga     # le certificat est émis dès que le DNS répond
Le certificat HTTPS est automatique et renouvelé sans intervention.
Ce que vous devez voir : The certificate for rhplus.ga has been issued, puis l’adresse répond en HTTPS.
Piège à éviter : la propagation DNS peut prendre de quelques minutes à quelques heures. fly certs check relancé plus tard suffit, rien à refaire.
12

Sauvegardes et exploitation

durée estimée : 5 min

Le logiciel sauvegarde déjà chaque jour à 02:00 (rotation 14 fichiers) ; Fly fait en plus des instantanés de volume.

bash
# sauvegarde immédiate, puis liste des fichiers
fly ssh console -C "gosu node node src/backup.js"
fly ssh console -C "ls -lh /data/backups"

# rapatrier une copie sur votre poste (hors site)
fly ssh sftp get /data/backups/.sqlite.gz

# suivi
fly logs                 # journal en direct
fly apps restart rhplus-saas-votrenom
fly volumes list         # état du disque

Règle des trois copies

Une sauvegarde qui vit uniquement sur la machine sauvegardée ne protège de rien. Rapatriez une copie par semaine sur votre poste ou dans un stockage objet : c’est la différence entre une démonstration et un service que vous pouvez vendre.

Ce que vous devez voir : un fichier rhplus-AAAA-MM-JJTHH-MM-ss-*.sqlite.gz d’environ 100 Ko à quelques Mo selon la taille de la base.
13

Mettre à jour le logiciel

durée estimée : 5 min

Chaque correction se publie avec la même commande ; les données du volume sont conservées.

bash
# modifier les fichiers, puis
fly deploy

# en cas de doute, les journaux de démarrage
fly logs
Piège à éviter : ne jamais exécuter fly scale count 2 : deux machines écriraient dans deux bases différentes. La montée en charge passe d’abord par une migration vers PostgreSQL (voir docs/HEBERGEMENT.md).
Piège à éviter : ne jamais supprimer le volume rhplus_data : toutes les données clients disparaîtraient, y compris les bulletins déjà émis et le journal d’audit.
